Native automation: documented command line, not a fabricated API
----------------------------------------------------------------
The manual explicitly documents batch/script automation for repeated analyses
and subsequent processing with MATLAB or Python/NumPy/SciPy (pages 32-34).

  Fastmean.exe -s "script.txt"
  Fastmean.exe -dir "working-directory" -s "script.txt"
  Fastmean.exe -o "circuit.scm" -s "script.txt"
  Fastmean.exe -o "circuit.scm" -sim [-exit]
  Fastmean.exe -o "circuit.scm" -ac [-exit]

The PDF prints typographic dashes; actual command-line arguments should use
ASCII hyphens. -sim starts transient analysis; -ac starts frequency analysis;
-exit closes FASTMEAN after the calculation. The manual does not document a
headless flag, stdout data protocol, process exit-code contract, COM, ActiveX,
DDE or an Automation object model. This does not prove no internal interface
exists; the supported integration evidenced here is the CLI and script file.

Working directories (page 32): initial folder is Fastmean.exe's folder; -dir
sets the working folder; -o changes it to the opened circuit's folder; starting
-s changes it to the script's folder. Relative script paths are resolved there
until a cd command. Absolute paths avoid this dependency.

Script command reference (pages 33-34)
-------------------------------------
Commands use NO leading period. Semicolons separate commands; % starts a comment
through the end of its line. Quote filenames/expressions containing spaces.
Use ordinary ASCII quotation marks in generated scripts. The PDF examples use
smart quotes for typography and contain a missing semicolon in one save_as
example; generated scripts should terminate every command consistently.

  cd "directory";
  open "circuit.scm";
  save;
  save_as "new-circuit.scm";
  save_netlist "elements.txt";
  write "samples.txt" expression1 expression2 ... expressionN;
  write after time_expression;
  define function_or_variable_definition;
  set element.parameter = expression;
  set variable = expression;
  element.parameter = expression;
  sim tmax=expression step=expression eps=value sv2scheme=yes|no;
  ac fmin=expression fmax=expression numpts=expression;
  exit;

Transient aliases: end_time, tmax and tend; time_step and step. eps is accuracy.
sv2scheme=yes copies final state-variable values into circuit initial conditions.
Missing sim arguments inherit saved circuit settings. The documented syntax
does not specify numeric minimum/maximum validation limits.

AC aliases: fmin/fstart, fmax/fend, numpts/pts. Missing ac arguments inherit saved
circuit settings. There is no documented script option for logarithmic versus
linear sweep; that setting belongs to the saved circuit/UI. There is also no
documented symbolic-analysis or graph-image-export script command.

Example generated transient script, requiring a circuit with OUT and R1:
  open "circuit.scm";
  write "samples.txt" t U(OUT) I(R1);
  sim tmax=10m step=1u eps=10u sv2scheme=no;
  exit;

Example AC expressions are f, MAG(U(OUT)/U(IN)), dB(U(OUT)/U(IN)), and
PHS(U(OUT)/U(IN)). The caller must choose actual existing element/port names.

Native numeric export and plotting
----------------------------------
Page 31 documents the schematic Text directives:
  .write "output.txt" expression1 expression2 ... expressionN;
  .write after expression
The script equivalents above omit the leading period. The result is a text
table of floating-point numbers, one calculation point per row. The manual does
not specify a CSV delimiter, column header format or numeric output precision;
the MCP must inspect actual output instead of assuming comma-separated CSV.

The MCP tool fastmean_export_netlist uses native save_netlist on a sanitized
recursive working copy, returns bounded text plus the full netlist/manifest
artifacts and requests no AC or transient analysis. timeout is per request,
between 1 and 60 seconds; cancellation terminates only its owned worker.

write after applies globally to all write directives and filters times before
the specified threshold. Only one such directive should exist per circuit.
The caller is responsible for unique output filenames across write directives.

Page 19: transient settings expose end time, calculation step and EPS. To request
approximately N steps, enter tmax/N as the step expression. There is no longer a
separate choice between a point count and step. Example screenshot settings are
tmax=1m, step=tmax/100, EPS=1m; these are examples, not specified default values.

Page 20: AC start frequency, end frequency and point count accept mathematical
expressions. Example screenshot shows 1 Hz, 1M Hz, 100 points and logarithmic
sweep. Transient and AC dialogs support 30 expressions with 7 visible rows.
Page 21: native graph axes can toggle linear/log scale and preserve zoom history.

Installed 6.1 static graph-related strings identify a Save data command and text
export filters *.txt and *.fra (frequency-response data), plus a Copy command.
No BMP/PNG/JPEG graph-file export command was established by these sources.
The MCP may render PNG plots from numbers calculated/exported by FASTMEAN, but
must label them as plots of native FASTMEAN data rather than native GUI captures.
A real screenshot of FASTMEAN is a separate output and needs an actual capture.

Expressions and units (manual pages 7-11, 27-28)
------------------------------------------------
Element/variable identifiers are case-sensitive; function names are not.
Parameter references require a named parameter, e.g. R1.R or L1.L, not R1/L1.
Numbers use decimal point. Engineering suffixes: p=1e-12, n=1e-9, u=1e-6,
m=1e-3, k=1e3, M=1e6, G=1e9; uppercase M and lowercase m differ.
Operators are + - * / ^ with parentheses; constants include e and PI.
Variables t and f represent time and frequency. Complex inputs use i or j.

Signals include U(element_or_node), I(element), P(element); transient-only
stored energy W(...). Complex results should be explicitly reduced with RE,
IM, MAG, PH or PHS. If not reduced, the displayed real part is used. dB(z) is
20*lg(abs(z)); PH/PHS return degrees and PHS unwraps 360-degree discontinuities.
Other documented functions include sin/cos/tan/cot, their inverses, hyperbolic
functions, ln/lg, exp/abs/sqrt/pow, limit, max/min, floor/round/mod, last,
AVG/RMS, FFT, wnd, and transient harmonic-extraction tmag/tph/tre/tim.

Element parameter expressions are evaluated once at the start of each analysis
and cannot depend on time, currents or voltages. Logical elements do not support
this general parameter-expression feature. .define/.def on a schematic defines
variables/functions. An example symbolic export sets p=i*2*PI*f before defining
the formula, permitting frequency plots of the derived expression in FASTMEAN.

Symbolic/equation scope
----------------------
Manual pages 22-23 document Laplace-domain currents/voltages and, since 6.0,
ratios yielding transfer functions, impedances and admittances. Named ports can
be test points. Output supports copying as ordinary text, Maple text, .define
text, or an image. The official page identifies the SCAD/CIRSYM native core.
This is symbolic linear-circuit analysis; no general arbitrary-equation solver
or nonlinear symbolic solver is documented. The page lists passive R/L/C,
transformers, independent/dependent sources, gyrators, op amps and summators
among supported symbolic elements. Gain >=1e15 denotes an ideal op amp.

The official page warns of sign conventions based on node ordering: voltages
point from larger to smaller node number; resistor current uses that direction,
while other element currents use the opposite direction. A consumer should
retain native node/sign information rather than silently change formula signs.

Native scheme format / constraints
----------------------------------
Pages 24-26 document YAML .scm files from version 6.0 onward, allowing external
programmatic reading/writing/generation. Earlier files were binary and
undocumented. The example contains Objects, endpoint-ID/pin Wires, TD settings
and expressions. It is a partial example, not a complete normative schema.
Pages 11-15 require a ground in every galvanically isolated island and discuss
topology constraints. The installed DEMO dialog resource states a 50-element
analysis limit, disabled undo/clipboard functions and periodic demo prompts.
License/runtime behavior must be observed; the MCP must not bypass licensing.

Adapter contract (version 1.6.0)
---------------------------------
This stdio server exposes 29 tools. It creates/edits native YAML SCM projects,
uses the separately installed FASTMEAN/CIRSYM engines, and returns registered
files and MCP images without desktop automation. Deliver the complete returned
project folder; opening a GUI is an explicit fastmean_open action only.

Catalog and authoring
---------------------
Call fastmean_catalog(query="TR3",detail=true) before using an unfamiliar kind.
The catalog inventories 56 accepted native factory TypeIDs in FASTMEAN6.1:
44 ordinary electrical classes, 6 service classes, 2 internal auxiliary sources
and 4 legacy source aliases. These categories are not interchangeable.
All 44 ordinary classes are supported for authoring/native numerical use:
R,C,L,UNISTOR,NLC,NLL,NLR,D,FSW,U,I,G,E,F,H,GYR,TR,TR3,TUBE,NMOS_SMALL,NPN,
OPAMP,OPAMP_SAT,PWM,PAM1,PAM2,BALMOD,SW,THYRISTOR,MOSFET,LINE,BRIDGE,RS,DFF,
JK,RSCLK,NOT,AND,OR,XOR,LATCH,COMP,SUM,X.
X uses create_project and validated portable model definitions. Numerical
operational coverage, quantitative oracles and static geometry are separate
catalog evidence; inclusion is not calibration of every physical model.

a component needs kind,name,nodes and value or declared numeric parameters.
Use exact catalog pin order. Unknown fields, nonfinite values, unbounded arrays
and unsafe file interfaces are rejected. Numeric defaults are adapter templates,
not promised GUI defaults. Generation does not accept arbitrary scripts or
SPICE imports. Node0 is native global ground; names are ASCII identifiers.
External ports map public aliases to graph node names; do not replace ordinary
wires with a port at each component pin. With numeric graph nodes use named
aliases, e.g. ports={"IN":"17","OUT":"31"} and signals U(IN),U(OUT).

U/V nodes are [positive,negative]. I nodes are [from,to], positive current from
first to second; I=[0,out],1mA into R=1kohm gives +1V. D=[anode,cathode].
TR=[p1,p2,s1,s2], n=Np/Ns; pins1 and3 are dotted. TR is ideal and stores no
magnetic energy: add a separate magnetizing L for flyback. SW nodes are
[control+,control-,switch1,switch2]; Ron>0,Roff>=Ron,Uoff<=Uon. Control above
Uon turns on; below Uoff turns off; hysteresis preserves intermediate state.
OPAMP6400=[noninverting,inverting,output], Uout=k*(Uplus-Uminus), referenced to
global ground, without supply pins or physical current/bandwidth limits.
SUM7000=[output,common,input1,...],N=1..5,k is the coefficient list.
AND/OR/XOR use N input pins followed by output,N=2..8. DFF/JK HasRS adds two
asynchronous pins. BALMOD has3 physical pins; its internal fourth node is not
an external terminal. Query detail for remaining parameter and geometry data.

Sources and time semantics
--------------------------
U and I expose all5 native modes: dc,sine,pulse,triangle,pwl. waveform accepts
mode-specific amplitude,frequency,phase,delay,high,low,duty_percent,rise_time,
finite_duration,periods,points,time_scale,scale,offset,periodic. PWL points are
2..4096 finite [time,value] pairs with strictly increasing time. Numeric SI
suffixes use p,n,u,m,k,M,G; m and M differ. Unicode unit literals are normalized
before native execution, without rewriting native mathematical expressions.

Public waveform.delay is ALWAYS seconds. Native sine/pulse/triangle Delay is
periods, converted with F; dc/PWL Delay is seconds. delay_periods is an explicit
alternative to delay for periodic analytic modes. Native PHI0 zero is a cosine
reference in checked6.1; phase=-90 gives sine. finite_duration gates the sine to
periods (fractional NP allowed); otherwise NP is ignored. PWL periodic=false
linearly extrapolates after its last point; periodic=true repeats for NP periods
and then returns zero. Preserve native timing; do not shift samples to match an
ideal curve. edit_values patches requested source fields and preserves omitted
and inactive mode data. Raw native parameter editing retains native units.

Layout and preview
------------------
Default density="compact" uses adjacent components and real orthogonal wires.
Use layout.placements,nodes,ports,routes for reference placement; explicit
coordinates are integers on a4-unit grid, rotations0..3. layout.nodes are soft
routing hints; exact routes require orthogonal connected polylines. Unused
branches may be pruned. Different-net collinear overlaps and ambiguous
junctions are rejected; plain perpendicular crossings are unconnected.
layout.ground_style="rail" is the common return; "local" places native GND near
grounded pins. Explicit node0 routes require rail. Components may require manual
coordinates when labels or the graph make automatic placement inadequate.

Degree-two CON corners are removed only when endpoint-derived native bends
reproduce the route. Branches, required waypoints and intentionally open-pin
endpoints remain. A single free pin gets a short wire and one CON, not a fake
load or external port. relayout always creates a new portable copy, retains
saved settings, and verifies terminal connectivity. Unknown geometry, unstable
numeric-node probes or unsupported model interfaces must fail explicitly.
Preview PNG/SVG is an MCP engineering drawing, not a FASTMEAN screenshot.
Some catalog symbols are functional blocks using native pin anchors, not exact
GUI glyphs. Review every important scheme. include_text=false hides notes only
in the image; original TEXT and parameter expressions remain in the SCM.

Hierarchy and parameters
------------------------
create_project accepts models:{MODEL:{pins:{Left:[...],Top:[...],Right:[...],
Bottom:[...]},circuit:{components:[...],ports:{...}}}},circuit:{...}.
Instances use kind:X,name,model,connections mapping every declared pin.
Up to99 definitions and32 public pins per model; names are case-unambiguous
ASCII. Native interface order is Left,Top,Right,Bottom then per-side list order.
Child PORT geometry determines binding: LeftRot2/RightRot0 sort byY;
TopRot3/BottomRot1 sort byX. Manual child positions must preserve this order.
Native X requires standard fonts, General.Scale100, short relative filenames.
Project outputs include main.scm,models/*.scm,project.spec.json and hashes.
Change topology by editing the published JSON then create_project again.

Active recursive models are rejected. A cycle through a child underscore test
element can be finite: root test elements are active; child underscore elements
and inactive subtrees are excluded exactly as native expansion does. Original
and private model hashes are retained. Shared instances have separate nodes.
Numeric instance parameter overrides via native Scm/Actual are not authored.
Per-instance analysis IC/source-bias preparation clones private model branches
so that siblings sharing a definition remain unaffected.

annotate_circuit saves root numeric .parameter values, TEXT explanations and
TD/FD expressions in a new copy. Legacy bindings={"R1":"R0"} and typed fields
bindings={"TR1":{"n":"Ratio"},"VIN":{"PULSE.F":"Fswitch"}} are supported.
Only declared scalar electrical fields may bind; files, model interfaces,
structural enums and logic parameter expressions are excluded. edit_parameters
changes existing finite numeric root constants, preserving binding expressions,
comments and child models. It checks known literal ranges but is not a CAS.
edit_values replaces selected element literals; edit_properties patches declared
native parameter fields/tables and saved TD/FD/AOD/SOD/DCOP settings, with
optional definitions=[{name,expression,arguments?}] saved as native .define TEXT.
N/HasRS edits changing terminal count require a regenerated connected scheme.

inspect returns critical metadata/root_parameters plus byte-bounded sections:
components,nodes,objects,texts,ports,parameters,analysis,wires,warnings,
parameter_issues. Use section,offset,limit and next_offset; detail_path reads
complete nested fields/chunks. expected_source_sha256 detects concurrent saves.
No arbitrary file-read endpoint is provided. Model/file directives are validated
before a native job; external DLL execution is not exposed.

Numerical analyses
------------------
ac and transient use native batch scripts in fresh private jobs. definitions is
a bounded list of {name,expression,arguments?}; overrides maps native variable
or qualified component.parameter names to mathematical expressions. No script,
command separator or caller-selected output filename is accepted.
AC points2..10000,scale=log|linear. TD stop/step are seconds,eps in(0,.1],
step budget<=1e6,signals<=30. Omitted signals select active saved f/t traces;
custom saved XY plots need explicit expressions. Native exports must cover the
requested interval and AC grid. Missing columns or partial outputs are errors.

transient supports sample_after,initial_conditions=scheme|zero|dc or an IC map,
and state2scheme=true to save final IC in a separate SCM. Saved-state files are
not imported. DC uses native DC initialization with zero-duration export, not a
fabricated undocumented dc script command. source_values explicitly replaces
non-DC waveforms for this private DC calculation. Source ramps/delays are cleared
only in that working copy and recorded. sweep(target,values,analysis,settings)
runs1..32 separate calculations from an immutable prepared project snapshot.
Each point retains actual native files/provenance. TD sweeps with postfunctions
use the summary path; settings.fft selects nativeFFT. A run timeout/cancel stops
only that owned worker, never user windows or unrelated processes.

Transient events may repeat timestamps; retain both event states in native
order. Equal-time jumps add zero integral; extrema include all states.
U/C ideal-source loops, including verified active model boundaries, are checked
before TD. Partial coverage is explicitly reported, not claimed as complete
singularity analysis. Do not insert invented resistance or replacement samples.

Native postprocessing versus NumPy spectrum
------------------------------------------
evaluate signals may use native last,AVG,RMS or harmonic functions; summary
exports are actual native final tables, not fake time-series axes. NativeFFT
requires FFT expressions and fft={window:[start,end],points:1024,harmonics:40,
window_type:0}; native window_type0..3. A separate time writer proves coverage
and FFT frequencies are checked. harmonics extracts up to7 requested frequencies
via native tre,tim,tmag,tph over window=[start,end]seconds. FASTMEAN calculates
these values; Matplotlib renders their charts.

spectrum is a DISTINCT NumPy rFFT of native TD samples: points16..262144,
window_function=hann|rectangular|hamming|blackman|bartlett. Native event-aware
piecewise interpolation produces a uniform grid. The result retains native CSV,
window,amplitude/phase/PSD normalization and provenance. Interpolation creates no
new physical bandwidth; choose a sufficiently fine native calculation step.
Do not label this NumPy transform a native FFT or native window screenshot.

Symbolic contract
-----------------
Native FASTMEAN exports and expands connectivity before CIRSYM conversion.
Linear zero-state R/C/L/U/I,G/E/F/H,OPAMP,TR/TR3,GYR,SUM,UNISTOR are supported,
including X made of these classes. analysis=voltage|current|transfer|impedance|
admittance selects U/I/H/Z/Y. output_reference defines voltage polarity;
output_element selects current; input_source identifies the independent drive.
Normalized H/Z/Y requires one independent source; output-only equations may
contain several. Actual numeric native parameter values enter CIRSYM. Current
sensors are inserted in series. Short unique aliases avoid native long-name
collisions; the mapping back to user/model names is retained. CIRSYM supplies
the expression; only documented substitutions and input-amplitude division are
performed by the adapter. This is not an arbitrary/nonlinear equation solver.

Registered artifacts and clients
--------------------------------
plot takes a registered completed run_id and exact existing columns,panels,
display_window,measurement_window,title,subtitle,x_unit. It starts no simulation
and does not recompute selected formulas. TD RMS/mean use window-boundary
interpolation and trapezoids on adaptive native samples before decimation.
PNG/SVG,chart spec,measurements and provenance are published. Source CSV hashes
are verified; modified data is rejected. get_result reopens saved MCP images;
read_data pages rows; list_runs finds jobs. Reads expose registered outputs only,
not arbitrary local files. See docs/PLOTTING.md for arguments and metric limits.

Claude Code/Desktop,Kimi CLI,DeepSeek through Cline and generic stdio clients
can use the same server. client_config exports local connection JSON; model
credentials belong to the client. The MCP needs no model-provider keys.

Known boundaries
----------------
DIGITAL_IN410/DIGITAL_OUT420 are external DLL-module pin bindings, not regular
PORT400 subcircuit terminals. Their alias.pin names refer to a module declared
with Directives/.dll alias/file_name. Unbound contacts can crash native6.1.
MCP does not generate/load this unsupported external-DLL context. Internal
U_AUX2011/I_AUX3011 and legacy source aliases are not ordinary new components.
No claim is made to automate every GUI dialog, parse pre6.0 binary SCM, import
arbitrary SPICE/device models or bypass native DEMO/license constraints.
No Windows locale,registry,PATH or security setting is changed. FASTMEAN Russian
UI is a separate optional project. Portable and opt-in native tests are separate;
see docs/VALIDATION-1.6.0.md for actual checks, not an assumption of universal
compatibility or unrun CI success.
